> **Update — September 2026**: Valheim 1.0 and Deep North were released on September 9, 2026. Launch-era guidance below should be read alongside the September 11 hotfixes, including the Steam achievement opt-in. See [patch notes](/patch-notes).

Valheim 1.0 is a major game update, and existing mods should be treated as **unconfirmed until their authors test the final release**. Iron Gate does not provide official mod support and does not guarantee that mods will function with 1.0.

There was no pre-release public test branch for 1.0. Mod authors and server operators can now test against the released build.

## The confirmed mod situation

Iron Gate's 1.0 FAQ confirms:

- Valheim has no official mod support.
- Existing mod compatibility is not guaranteed for 1.0.
- There is no Steam Workshop integration for 1.0.
- Consoles have no mod support in 1.0.
- There was no pre-release public test branch for 1.0.

That does not mean every mod will break. It means there is no official compatibility promise, and the correct status for an untested mod is **unknown**, not compatible.

## Before updating a modded installation

For every modded character, world, or server:

1. Stop the game or server cleanly.
2. Create an offline backup of the world and character data.
3. Export the exact mod list, loader version, and configuration files.
4. Record the current Valheim application version.
5. Keep a copy of the working pre-1.0 installation where licensing and platform tools permit it.
6. Decide which mods are essential and which can be removed for the first test.

Do not depend on an automatic backup stored beside the live world. A launcher, hosting panel, or synchronization tool may update more than expected.

## A safe compatibility test order

Use a duplicate world and add complexity in stages:

1. Launch the 1.0 client without mods.
2. Load a disposable copy of the world locally.
3. Confirm terrain, builds, storage, portals, and character inventories.
4. Install a loader version explicitly marked for the final 1.0 build.
5. Add required framework mods.
6. Add gameplay or content mods one at a time or in small groups.
7. Review logs after each stage.
8. Start the dedicated server only after the local baseline is understood.
9. Require clients to use the compatible versions expected by the server.

Never save a partially loaded modded world over the only good copy. A missing building or inventory object may become permanent once the altered state is saved.

## BepInEx and other community tooling

BepInEx, mod managers, and individual mods are community projects rather than supported Valheim features. Their compatibility announcements should come from their maintainers.

A hosting panel offering a one-click BepInEx installer does not prove that the installed version supports Valheim 1.0. Check the installed version, the provider's update status, and the upstream release notes before loading a valuable world.

Avoid downloading replacement DLLs from repost sites or links shared without provenance. Use the mod author's documented distribution channel and keep a record of what was installed.

## Dedicated-server checklist

Modded servers add four compatibility layers: the Valheim server build, the loader, server-side mods, and player-client mods.

- [ ] Back up the live world and permission files.
- [ ] Copy loader and mod configuration.
- [ ] Record every mod and version.
- [ ] Disable automatic restarts during the maintenance window.
- [ ] Update the base server before adding mods.
- [ ] Test the server without mods on a duplicate save.
- [ ] Confirm each required mod supports the final build.
- [ ] Tell players which client mods and versions are required.
- [ ] Verify crossplay expectations; consoles cannot install client mods.
- [ ] Keep the rollback set until several successful sessions have completed.

See [updating a Valheim server](/servers/updating-a-server) and [world backup and restore](/servers/world-backup-restore).

## Mods and crossplay

Valheim 1.0 supports crossplay between all launch platforms, but consoles have no mod support. Therefore, do not assume a modded PC server remains compatible with PlayStation, Xbox, or Nintendo Switch 2 clients.

Some server-side changes may appear transparent to clients, while others require matching files or change network behavior. That distinction is defined by each mod, not by Valheim's general crossplay promise. For a mixed-platform group, a clean server is the dependable launch baseline.

## Mods and achievements

The September 11 Steam hotfix explicitly allows achievement opt-in after developer-command or mod use. See the [hotfix summary](/patch-notes/v1-0-12).

This is not a guarantee of mod compatibility. Check achievement eligibility in the installed build and review the [achievement guide](/valheim-1-0/achievements-cheats).

## Steam Workshop and console support

There is **no Steam Workshop** support in 1.0. PC modding continues through community tooling at the user's own risk.

There is **no console mod support** in 1.0. This applies to the newly released PlayStation 5 and Nintendo Switch 2 versions as well as existing console players.

## Frequently asked questions

### Will Valheim mods work after the 1.0 update?

Some may work, but Iron Gate guarantees none of them. Wait for the author of each required mod to test the final 1.0 build.

### Will Valheim 1.0 have Steam Workshop support?

No. Iron Gate says Steam Workshop will not be featured for version 1.0.

### Will BepInEx work with Valheim 1.0?

Treat compatibility as unknown until the BepInEx maintainers and the relevant Valheim modding tools confirm support for the final release. A preinstalled hosting-panel option is not itself proof.

### Can console players use Valheim mods?

No. Iron Gate says consoles will not have mod support for 1.0.

### Should a modded server start a new world?

Not automatically. Back up the existing world and test a copy without mods first. A new world provides a cleaner diagnostic baseline, but preserving the original save is still essential.
